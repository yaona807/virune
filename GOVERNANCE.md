# Virune Project Governance

日本語: [GOVERNANCE_ja.md](GOVERNANCE_ja.md)

## Governance

Virune is currently an open-source project maintained solely by [`@yaona807`](https://github.com/yaona807).

There is currently no steering committee or voting process. The maintainer makes the final decisions for the project.

## Maintainer responsibilities

The maintainer is primarily responsible for:

- triaging Issues and reviewing and merging Pull Requests;
- setting project direction and priorities;
- releases and distribution;
- security response;
- community moderation.

See [CONTRIBUTING.md](CONTRIBUTING.md) for how to contribute, [SECURITY.md](SECURITY.md) for reporting security issues, and [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md) for community conduct.

## Decision making

Routine changes are developed publicly through Issues and Pull Requests.

For changes with significant impact on users, including changes to the language specification, public APIs or ABIs, or compatibility, the change and its impact are made clear before a decision is made.

For important decisions, the maintainer explains the reasoning in the relevant Issue or Pull Request whenever practical.

## Adding or changing maintainers

There is no automatic path to becoming a maintainer based on contribution count, time in the project, or similar factors.

If a new maintainer is added, their responsibilities and permissions will be documented.

There is currently no automatic process for transferring project administration if the sole maintainer becomes unavailable for an extended period.

## Changing this document

Changes to project governance are proposed publicly through an Issue and Pull Request, with the change and its rationale explained.

`GOVERNANCE.md` and `GOVERNANCE_ja.md` are updated together in the same Pull Request.
