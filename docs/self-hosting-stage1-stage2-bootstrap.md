# Actual Stage 1 and Stage 2 bootstrap

The Stage bootstrap runner performs two real compiler generations through the executable Self-host MVP boundary.

1. The existing Stage 0 project build is normalized and loaded as an executable compiler candidate.
2. Stage 0 compiles the canonical Self-host MVP source input and produces the Stage 1 compiler artifact.
3. The Stage 1 artifact is materialized and loaded as the next compiler candidate.
4. Stage 1 compiles the same source input and produces Stage 2.
5. The existing bootstrap shadow report requires Stage 1 and Stage 2 to differ only at `metadata.stage`.

## Evidence boundaries

Both stages are bound to the same canonical source-manifest SHA-256. Each generation emits separate evidence containing:

- the stage being generated;
- the compiler artifact SHA-256 that performed the generation;
- the source-manifest SHA-256;
- the generated artifact SHA-256;
- the generated compiler entry module.

The input compiler SHA is deliberately kept outside normalized artifact metadata. Stage 1 is generated by Stage 0 while Stage 2 is generated by Stage 1, so placing that SHA inside the artifacts would create a legitimate but unreproducible Stage 1／Stage 2 difference.

Generation evidence is non-promotable by itself and always records `productionEligible: false`.

## Current scope

The current runner targets the single-source Self-host MVP compiler. It does not switch the Production Parser／Checker, update the fixed Seed, change workflows or branch protection, or authorize promotion. Multi-module Kernel self-generation remains a later extension of the same boundary.

## Failure policy

The runner fails closed when compilation is rejected, an error diagnostic is emitted, the compiler entry is missing or ambiguous, the generated artifact contains an unexpected source map, or the Stage 1／Stage 2 shadow report contains any unexplained difference.
