# JavaScript相互運用における第三者パッケージの配布境界

[英語版](js-interop-distribution.md)

この文書は、JavaScript / TypeScript相互運用で第三者の宣言ファイルや実装をどこまで解析に使い、どこからを再配布として扱うかを定めます。Viruneは外部パッケージの利用や再配布を許諾せず、パッケージのライセンス種別をコンパイラの安全性Evidenceとして扱いません。

## `[interop.third-party-distribution]` 第三者パッケージの配布境界

### 宣言ファイルは解析に使い、再配布しない

JavaScript相互運用Providerは、具体的な利用方法の解決に必要なTypeScript宣言ファイル、プラットフォーム宣言、パッケージ情報、宣言間の依存関係を読み取れます。これらは第三者の資料のままです。

Providerに依存しない安定したExternal / Foreign IR、配布対象となる再現性Evidence、Viruneの生成コードには、解決結果に必要な意味情報だけを含めなければなりません。宣言ファイルの本文、宣言内のドキュメントコメント、宣言を機械的に再現したテキスト、絶対パス付きで保持した宣言ソースの内容、`ts.Type`、`ts.Symbol`、ASTノード、`Program`などのTypeScriptコンパイラの生オブジェクトを含めてはいけません。

安定したEvidenceには、解決結果の再現や説明に必要な最小限の識別情報を保持できます。たとえば、モジュール名、エクスポート名またはプロパティ名、パッケージからの相対位置に正規化した宣言位置、正規化した型表示、パッケージとProviderの識別情報とバージョン、ハッシュ、`module-resolution witness`のメタデータです。

### 生成JavaScriptは外部パッケージを参照する

通常のDirect External Semanticsでは、外部の実行時依存を通常のJavaScript importと操作で参照しなければなりません。Direct相互運用のために、依存パッケージの実装を生成コードへコピーしてはいけません。

コンパイラが生成するcallable shim、bridge helper、そのほかの境界コードはVirune自身が生成するコードです。第三者の宣言本文、ドキュメント、実装本文をコピーして生成してはいけません。

### 技術的な互換性はライセンス許諾ではない

各外部パッケージには固有のライセンス条件があります。利用者と配布者は、利用・配布方法に応じてその条件を満たす責任があります。

Direct、Managed、Adapter、Host、Unsafeは、技術上の相互運用境界だけを表します。法律上またはライセンス上の分類として扱ってはいけません。依存パッケージのライセンス種別を、TypeScriptによる利用方法の解決、External operationの選択、相互運用の安全性判断に使ってはいけません。

### バンドルは別の配布境界として扱う

Viruneの配布物にTypeScriptやその他の第三者実装を実際にバンドルする場合は、リポジトリにある既存の決定的なライセンス / NOTICE / SBOM収集とリリース検証を適用します。バンドル対象パッケージのライセンス上の出所情報が欠落、矛盾、または未解決である場合は、既存のリリースポリシーに従って安全側に失敗しなければなりません。

下流のViruneアプリケーションだけが使う外部パッケージを、Virune自身のリリース内容として暗黙に扱ってはいけません。

### 永続的なバインディング生成は別途レビューする

将来、`.d.ts`からViruneバインディングのソースを生成するなど、変換した宣言内容を永続化または再配布する機能は別の配布機能です。導入する場合は、元ソースの出所、コピーするコメントやドキュメント、生成ファイルの帰属、再配布義務を含む明示的な設計・ライセンスレビューが必要です。Direct External Semanticsの実装の都合で暗黙に追加してはいけません。
