# JavaScript相互運用における第三者パッケージの配布境界

[英語版](js-interop-distribution.md)

この文書では、JavaScript / TypeScriptとの相互運用で第三者の型宣言や実装をどこまで解析に利用し、どこから再配布として扱うかを定めます。Virune自体が外部パッケージの利用や再配布を許可するわけではありません。また、ライセンスの種類をコンパイラーの安全性の証拠として扱うこともありません。

## `[interop.third-party-distribution]` 第三者パッケージの配布境界

### 宣言ファイルは解析に使い、再配布しない

JavaScript相互運用のProviderは、実際の使い方を確認するために、TypeScriptの宣言ファイル、プラットフォームの宣言、パッケージ情報、宣言間の依存関係を読み取れます。ただし、これらのファイルは第三者の資料であり、Virune自身の資料になるわけではありません。

Providerに依存しない`External` / Foreign IR、配布する再現性の証拠、Viruneが生成するコードには、型の解決に必要な意味情報だけを含めなければなりません。

第三者の宣言ファイル本文、宣言内のドキュメントコメント、宣言を機械的に復元したテキスト、絶対パス付きで保持した宣言ソースの内容、`ts.Type`、`ts.Symbol`、ASTノード、`Program`など、TypeScriptコンパイラー内部のオブジェクトを含めてはいけません。

安定した検証結果には、型の解決結果を再現・説明するために必要な最小限の識別情報だけを保持できます。例えば、モジュール名、エクスポート名やプロパティ名、パッケージからの相対位置に直した宣言位置、正規化した型表示、パッケージとProviderの名前・バージョン、ハッシュ、`module-resolution witness`のメタデータなどです。

### 生成JavaScriptは外部パッケージを参照する

通常のDirect External Semanticsでは、実行時に必要な外部パッケージを、通常のJavaScriptのインポートや操作を通して参照しなければなりません。直接相互運用するために、依存パッケージの実装を生成コードへコピーしてはいけません。

コンパイラーが生成するコールバック用のshimや変換用ヘルパーなどは、Virune自身の生成コードです。第三者の型宣言、ドキュメント、実装の本文をコピーして生成してはいけません。

### 技術的な互換性はライセンス許諾ではない

各外部パッケージには固有のライセンス条件があります。利用者と配布者は、利用・配布方法に応じてその条件を満たす責任があります。

Direct、Managed、Adapter、Host、Unsafeという区分は、技術的な相互運用の方法を表すものです。法律上やライセンス上の分類ではありません。

パッケージのライセンスの種類を、TypeScriptでの呼び出しの解決、`External`操作の選択、安全性の判断に使ってはいけません。

### バンドルは別の配布境界として扱う

Viruneの配布物にTypeScriptなど第三者の実装を実際に含める場合は、リポジトリにある決定的なライセンス・NOTICE・SBOMの収集処理とリリース検証を適用します。パッケージのライセンス情報の出所が欠落・矛盾・未解決の場合は、既存のリリースポリシーに従って安全側に失敗しなければなりません。

下流のViruneアプリケーションだけが使う外部パッケージを、Virune自身のリリース内容として暗黙に扱ってはいけません。

### 永続的なバインディング生成は別途レビューする

将来、`.d.ts`からViruneバインディングのソースを生成するなど、変換した宣言内容を永続化または再配布する機能は別の配布機能です。導入する場合は、元ソースの出所、コピーするコメントやドキュメント、生成ファイルの帰属、再配布義務を含む明示的な設計・ライセンスレビューが必要です。Direct External Semanticsの実装の都合で暗黙に追加してはいけません。
